# 文本如何分块？分块策略和优化方法？

## 固定大小分块

按字符或 token 数切分，如 512 token 一块。实现简单，但可能切断句子和条件。字符数不等于 token 数，应按模型 tokenizer 检查输入长度。

## 基于内容的分块

- **按分隔符分块：** 利用段落、Markdown 标题、HTML 标签等自然结构。
- **按句子分块：** 先分句，再组合相邻句子；仍需注意跨句指代和条件。
- **递归分块：** 优先按大边界切分，超长部分再细分；中文不能只依赖空格。
- **语义分块：** 根据相邻句子或窗口的相似性变化划分边界，增加编码成本且依赖阈值，不保证优于结构分块。

## 扩展分块方法

- **父子分块（Parent-Child / Small-to-Big）：** 检索小块，再扩展到父块补齐上下文。需处理父块存储、返回去重、权限和长度预算，不保证质量一定更好。
- **上下文增强（Contextual Retrieval）：** 先分块，再结合原文为每块生成简短上下文说明，前置到块文本中用于 embedding 和 BM25 索引。说明需核验，它增强块表示，不是决定分块边界。
- **延迟分块（Late Chunking）：** 先整体编码长文本得到 token 表示，再按块边界分别池化，形成块向量；不是先池化全文再分块。需要适配模型与实现，仍受窗口限制。

## 优化方法

- **设置重叠（Overlap）：** 缓解邻接边界断裂，但不能保证语义完整；过多重叠会增加存储和重复结果。
- **添加元数据：** 保存来源、版本、章节、页码或位置、父子关系和权限。数值、单位与条件尽量保持关联。
- **多尺度分块：** 小块检索与较大上下文返回可配合使用，但增加索引和去重成本，需验证收益。
- **调整参数：** 比较证据召回、答案质量、token、索引体积和延迟；分块改变后按原文证据重新映射标注，避免旧块 ID 造成不可比。

> [!question] 面试追问
> **Q：chunk size 偏大 / 偏小，优缺点各是什么？**
> **A：** 大块可能更完整，但容易混主题、引入噪声和增加成本；小块更聚焦，但可能缺少主体与条件。256—1024 token 可作为实验范围，不是固定标准，还需考虑模型窗口和截断。
>
> **Q：父子分块与「小块 + overlap」本质区别是什么？**
> **A：** Overlap 在相邻块中重复部分文本；父子分块在命中小块后扩展上下文。前者简单、覆盖局部，后者灵活但需控制噪声和预算；父块去重取决于实现。
>
> **Q：几百页、层级复杂的手册/合同怎么设计分块与索引？**
> **A：** 按标题层级切分，超长部分继续细分，保留章节路径。可使用父子分块或多级索引，但父块不必是整章，粗层漏检也可能影响结果，要与直接细粒度检索比较。
