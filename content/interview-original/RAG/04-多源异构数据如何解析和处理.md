# 多源异构数据如何解析和处理？

## 解析（Parsing）

按文件类型提取文本、结构和元数据：

- **PDF：** PyMuPDF、pdfplumber、Unstructured 等，检查文字编码、阅读顺序和表格效果。
- **PPTX：** python-pptx 等，注意文本框、图表和备注的处理范围。
- **Word：** python-docx 适用于 DOCX；旧 DOC 需要其他解析或转换路径。
- **HTML：** BeautifulSoup 等配合正文抽取，动态内容可能需要先渲染。
- **Markdown：** 按标题、列表、代码块和表格等结构处理。

复杂内容需专门处理：

- **扫描件 / 图片：** 用 PaddleOCR、Tesseract 等 OCR，检查数字、单位、否定词和漏识别。
- **表格与公式：** 保留表头、行列关系、变量与单位。简单表格可转 Markdown，复杂表头可用 HTML 或结构化数据；不能保证转换后无信息损失。
- **多模态解析：** VLM 可辅助版面、图表及语义抽取，但需核验并保留原图来源。

MinerU、Docling、LlamaParse、marker 等也可作为一体化解析候选。用代表性文档比较质量、速度和成本，不预设某工具一定更优。

## 处理（Processing/Preprocessing）

1. **清理（Cleaning）：** 保留原文，有依据地去掉重复页眉页脚、广告等噪声；脚注、水印可能有用，不宜一概删除。
2. **标准化（Normalization）：** 不默认统一小写、替换缩写或自动纠错，以免破坏型号、代码和术语；必要时生成单独的检索副本。
3. **文本规范化（Text Normalization）：** 词法索引按语言选择分词等处理；embedding 通常使用自身 tokenizer，不需要先人为词干化或去停用词。
4. **提取结构信息：** 保留标题层级、表头、单位、条件及来源位置，作为分块依据和元数据，并记录文档版本与权限。

解析后抽检文字覆盖、阅读顺序、数字单位、表格关系和来源映射，再通过下游检索与问答验证。增量更新时用文档 ID、版本和哈希识别变化，同步清理旧块和缓存。

> [!question] 面试追问
> **Q：扫描件、双层 PDF、多栏复杂版面如何兜底？**
> **A：** 扫描件用 OCR；双层 PDF 先检查文字层质量，合格则复用，否则重识别。多栏先还原阅读顺序，复杂页可尝试版面工具或 VLM，必要时人工复核。
>
> **Q：表格拆成单元格、还是转成 Markdown 再分块？**
> **A：** 重点是保留行列与表头关系。按行分块时携带表头、单位和键；复杂表格可保留结构化表示，跨页合并需核对列关系。精确统计可使用结构化查询或计算。
>
> **Q：图片信息如何转为可检索向量？**
> **A：** 用兼容的图文 embedding，或用 OCR/VLM 提取文字和图说进入文本索引，也可结合。保留原图映射，图说需核验；哪种更省取决于实际成本。
